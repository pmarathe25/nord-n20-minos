# Adreno streaming probe and ternary packing estimate

2026-11-10. A scratch OpenCL kernel streams a contiguous `uint4` buffer across 49,152 work items and XOR-reduces each work item's reads to a checked output. Input buffers were filled with a fixed pattern on the device. The event timer covers the streaming kernel, including its small output write, but the reported decimal GB/s counts input bytes only. It excludes allocation, fill, compilation and host readback. Each process took seven samples; the final run's 49,152 outputs passed the expected checksum. The sizes ran in forward and reverse order under the shared GPU lock, with CPU cores 0–2 at nice 15 and Minecraft running. This is a single simple access pattern, not a measured hardware peak or an upper bound on other kernels.

| Input | Median time, first / second process | Input throughput, first / second |
| ---: | ---: | ---: |
| 8 MiB | 0.550 / 0.555 ms | 15.25 / 15.11 GB/s |
| 32 MiB | 2.242 / 2.260 ms | 14.97 / 14.85 GB/s |
| 128 MiB | 8.859 / 8.938 ms | 15.15 / 15.02 GB/s |

A later guarded sequence bracketed the real layer-0 Q2_0 decode kernels with the 8 MiB stream. The stream medians were both 0.549 ms (15.28 GB/s). The 9,216 × 2,560 up and 2,560 × 9,216 down projections took 1.188 and 1.195 ms respectively, with their existing sampled scalar checks passing. Each projection contains 5,898,240 code bytes plus 737,280 scale bytes. Dividing the 6,635,520 logical packed-weight bytes by the up time gives 5.59 GB/s; it is **not** a hardware traffic counter. Cache reuse, other reads and writes, kernel computation, queue timing, and different access patterns make it invalid to infer the actual off-chip bandwidth or prove a compute bottleneck from this ratio. At the contiguous stream rate, that many input bytes would take about 0.434 ms; that is only a reference calculation, not a lower bound for Q2 decode.

A recent [BITCOS paper](https://arxiv.org/abs/2609.16338) packs a presence bitmap and compact signs and measures results on x86 and Intel Xe2, not this GPU. For the previously counted layer-0 up matrix, 7,423,281 of 23,592,960 ternary values are zero. An idealized bitmap plus one sign bit for every nonzero, plus the existing FP16 scale per 64 values, needs 5,707,610 bytes versus 6,635,520 bytes for existing Q2_0, a **14.0%** reduction in logical weight bytes. That estimate ignores block alignment, indexing metadata, conversion, loading and unpacking. Even perfect proportional weight-bandwidth scaling alone is not an order-of-magnitude opportunity, and the stream comparison does not establish what fraction of the current projection could benefit. No BITCOS kernel or model-level comparison was implemented in this probe.

The scratch program is `wiki/experiments/n20-gpu-stream-bench.c`. Minimum observed available memory was 4,220,504 KiB, maximum battery temperature 25.4 °C. Minecraft passed its status query; no installed worker, model, firmware, server configuration or world was changed. Scratch weights, binaries and raw logs were removed.
