# Qwen3.5 0.8B speculative draft, November 10, 2026

The 0.8B Qwen3.5 model is an untested smaller autoregressive draft
candidate for Bonsai 2 4B. Unlike a replacement model, its proposed tokens
are checked by the target model. The candidate checkpoint is the
[ggml-org Q4_0 conversion](https://huggingface.co/ggml-org/Qwen3.5-0.8B-GGUF/tree/main)
at revision `807dfd9`, 563,036,064 bytes, SHA-256
`57d1997790d1744fba5b40a7317df71ea5e2acee28c47e78f0cce39c0703f8cf`.
The hash matched both the publisher's file metadata and the copy transferred
to the phone. The Qwen3.5 family match was a reason to test, not an assumed
guarantee of tokenizer compatibility.

## Desktop screen

The b12110 Vulkan server used Bonsai 2 4B Q2_0 as target, one slot,
2,048-token context, six CPU threads, and the existing grounded chat request.
It used a private copy of a cached Java Wiki archive and the Rust retriever.
All arms processed the same 12 factual and private-state questions in the
same order with temperature zero, a 140-token cap and prompt caching enabled.
The target and the draft both ran on Vulkan0. The middle arm used
`--spec-type draft-simple --spec-draft-n-max 4` with the 0.8B Q4_0 draft.
Each arm used a fresh server; the first request was included. Times cover
complete local HTTP requests, excluding retrieval and startup.

| Arm | Median request | Median prefill | Median decode | Accepted / proposed |
| --- | ---: | ---: | ---: | ---: |
| Target before | 288.5 ms | 88.3 ms | 177.1 ms | — |
| Target plus 0.8B | 500.0 ms | 128.5 ms | 383.7 ms | 250 / 352 |
| Target after | 273.0 ms | 84.2 ms | 165.7 ms | — |

The server successfully initialized and used both vocabularies. All 12
generated texts and finish reasons matched across the three arms. Median
reported cached tokens were 106 in each arm. These are limited deterministic
examples and timings from a desktop GPU, not a phone speed or general-quality
claim. The speculative server had no other deliberately scheduled desktop
GPU experiment during this comparison.

## Phone attempt

The Nord N20 ran an isolated Android ARM64 b12110 worker with the tuned
Q2_0, activation-texture, lazy Flash Attention-cache, server-prefix and
two-column recurrent patches. It used the installed 4B model, two efficiency
cores at nice 15, one 1,536-token slot, a 256-token microbatch, and a
private copy of the cached Wiki. The shared GPU lock serialized the test.
The live Minecraft server remained running and the Wiki enable marker stayed
absent. A guard sampled system available memory and battery temperature every
0.5 seconds, with a 1,200 MiB floor and a 40 °C ceiling.

The first target-only control warmed on an Observer request and then ran
the Shulker Box question through the real bridge and a private chat log and
console FIFO. The control reached health in 9.56 s; its warmup took 43.93 s,
and the chat-line-to-reply time was 40.43 s. It returned the correct cited
answer. The minimum sampled available memory was 2,256,336 KiB and the
highest sampled temperature was 25.0 °C. The recurrent layout trace confirmed
two columns. Texture selection was configured, but its normal informational
message did not appear in this build's log, so direct texture dispatch was not
independently confirmed in this run.

The 0.8B GPU draft loaded and the server became healthy, but its first
prompt aborted at `clSetKernelArg` with `CL_INVALID_KERNEL` in the Q4_0
flat-matrix path. The source skips compilation of that kernel on this old
Adreno compiler yet the dispatch selected it. A scratch-only backend then
fell back to a different existing Q4_0 kernel with matching argument and
launch layouts; the fallback executed, but its numerical equivalence was
not established. The guarded run crossed the 1,200 MiB floor during warmup,
before a complete answer. A reading after shutdown began was 1,204,920 KiB,
below the 1,228,800 KiB threshold. The monitor sent SIGTERM; the scratch
server was still exiting, so its verified process group was killed. Available
memory returned above 4 GiB and Minecraft remained running.

A second target-only control after the shutdown reached health in 9.31 s,
took 44.02 s for the same warmup, and returned the identical cited Shulker
reply in 40.52 s. Its minimum sampled available memory was 2,258,596 KiB
and its maximum sampled battery temperature was 25.7 °C. This checks that
the scratch inference path remained usable; it does not measure player tick
latency or long-running service behavior.

There is no complete draft reply, acceptance count, phone speed comparison,
or validated Q4 fallback from this attempt. The test does not justify using
this two-model GPU configuration. A different draft placement, backend fix,
or memory setup would need separate correctness, resource and full chat-path
measurements. No live model, firmware or service configuration was changed.
Minecraft answered a status query afterward. The phone's temporary model,
workers and cache copy were removed, and workstation scratch was moved to
the Recycle Bin after recording the results.
