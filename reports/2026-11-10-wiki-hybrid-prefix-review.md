# Scratch hybrid prefix checker review

2026-11-10. An independent review found that the experimental `n20-hybrid-prefix-trial.py` checker could accept a library search path that lexically appeared inside a hashed tree but resolved outside it; that it selected only the ordinary DSP module name even for the block-major runtime; and that it did not check whether artifacts changed between benchmark phases. It also left the DSP search directories, shell, optional GGML backend path and working directory insufficiently constrained.

The scratch checker now requires canonical existing library and DSP search directories covered by declared runtime trees, verifies the first OpenCL library-path match, identifies the known ordinary or block-major client URI, requires the corresponding module and a fingerprinted DSP shell, rejects `GGML_BACKEND_PATH`, and runs the benchmark from an empty private working directory. It re-hashes the caller-declared profile after each model run, before restore, and before publishing a newly seeded cache. Intermediate symlink paths are rejected by the file hasher. These changes can detect the tested changes, but they do not pin every input against a change-and-revert race or prove what arbitrary shared-object code loads.

The caller still has to identify and protect the actual firmware, its complete split blobs, GPU driver, DSP shell, linker, libraries, boot identity and other device inputs. The artifact roles are caller assertions, not an automatic attestation of running firmware. This helper remains a scratch experiment and must not be used as the production launcher's cache identity or considered a complete trust boundary. The previous [hybrid prefix measurement](2026-11-10-wiki-hybrid-prefix.md) used direct sequence-state APIs, not this wrapper, and its results are unchanged.

Validation: ten isolated tests passed on the phone under ARM64 Debian; the Windows run passed seven applicable tests with three POSIX-only cases skipped. The tests cover traversal and symlink rejection, library shadowing, both DSP module names, a changed shell/profile, mutation during seeding, rejection after a changed fresh run, nonempty working directories and dispatch-counter requirements. Both ordinary and block-major Android runtime binaries were separately compiled with warnings as errors, and their embedded module URIs were identified correctly. No model inference, installed service, firmware, or device configuration was changed. Temporary files and binaries were removed.
