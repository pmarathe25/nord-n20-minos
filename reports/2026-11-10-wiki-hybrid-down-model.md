# Scratch model integration of Hexagon down projections

2026-11-10. The [experimental runtime](../wiki/experiments/n20-hybrid-down-runtime.cpp) and [incremental backend patch](../wiki/experiments/llama-b12110-n20-hybrid-down.patch) add an opt-in 512-row Hexagon shard for the 2,560-by-9,216 FFN down projection. They use the parallel GPU activation packer and the 32-token-blocked HVX kernel measured in the [projection screen](2026-11-10-wiki-parallel-activation-pack.md). Gate/up retains its existing DSP kernel and pair reuse; [shape dispatch](../wiki/experiments/v66-q2-hvx-shape-dispatch.c) selects the blocked routine only for the supported down shard. Tensor kind is explicit in separate upload/project entry points: the full gate/up and down tensors have identical byte lengths. Both ION input buffers were enlarged for the longer down inputs. Unsupported tensors and failed dispatches retain the GPU fallback. This is not installed or production-ready.

The combined resident module passed full fixed-point integer and buffer checks with real layer-0 down weights at 128 and 33 tokens and gate/up weights at 128 and 16 tokens, including alternating inputs. A 33-token out-of-range input took all six expected GPU fallbacks. These checks do not cover every activation, output offset or shape transition. A separate full-model fault-only comparison injected 31 failures after the first DSP call of a two-call down projection; its first-logit hash and nine generated tokens matched an otherwise identical worker that bypassed those down projections before queueing. Both variants dispatched 31 shorter down projections. This checks one failure ordering, not every failure mode.

## Corrected prompt comparison

An initial 128/256-microbatch comparison used the prior approximate chat framing and produced only the beginning of a thinking trace. Inspection of the model's embedded chat template found that production's `enable_thinking: false` adds `<think>\n\n</think>\n\n` after the assistant header. The following test used that template suffix and trimmed system/user content as specified by the embedded template. It reconstructed the simple text-only framing locally; it did not call the server's `/apply-template` endpoint. Two offline Wiki questions used four retrieved passages each. The model worker used 128-token microbatches, warm shaders and an independently built 106-token in-memory system prefix for each arm. Prefix construction, model load, retrieval and game chat are excluded. Each result is one worker run, with the candidate bracketed by controls.

All six reached end of generation, and the grounded player replies matched between arms for each question. The observer reply met its existing expected-answer check. All three blast-furnace replies incorrectly said that a blast furnace can turn sand into glass; the cited excerpt concerned glass rather than establishing blast-furnace compatibility. A citation marker alone did not ensure support. Thus this small comparison shows no answer regression but does **not** establish satisfactory answer quality. The down candidate changed first-logit hashes, as expected from the additional Q8 arithmetic.

Candidate first-token times were 0.13–0.27 s lower for the blast-furnace question and 0.45–0.49 s lower for the observer question than their controls. This is a small two-question model-worker screen, not a robust chat-latency or gameplay result. Every candidate loaded 96 resident slots and dispatched all 93 attempted down projections with no fallback; controls loaded 64 slots and dispatched no down projections. The 96-slot limit leaves no spare slot, and failed uploads consume slot IDs in this scratch runtime. Startup, long-running memory pressure, concurrent players, broad factuality and additional model reloads remain untested; failures must continue to use the full GPU path. In the preceding approximate-frame 128-token test, candidates also dispatched all 155 down projections per worker; first-token differences varied by question. A 256-token screen used two sequential DSP calls for larger batches and did not establish a consistent gain on both questions.

Across the guarded shape, model, answer and fault trials, Minecraft was restored and passed its status query and CDSP returned offline with zero reported crashes. Minimum sampled available memory was 2,536,288 KiB and peak sampled battery temperature was 29.7 °C. The backend patch reverse-applied cleanly against the test source and both Android runtime and backend built successfully. No installed model, service, firmware, partition or world was changed. Private prompts, cached Wiki copies, binaries, vendor-image copies and raw logs were removed.
